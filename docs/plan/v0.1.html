F5 first, because the agent files and branch rules guide all the work after it. F1 next, so install and update exist before there's anything visible to install. F3 before the pane, because the pane's Board link reads what setup saves. F2 and F4 build the pane, and F4 depends on F2's frame. Each feature merges into main only after you approve it, so you get 5 merges in v0.1.

Step 0: spike

A scout agent (Haiku) and a researcher (Sonnet) check four things in about 30 minutes before any feature work. Nothing from the spike gets merged. Results go into docs/decisions.md.

  1. Can /studio update pull, update and reload the plugin by itself, or do you have to run /reload-plugins after?
  2. Can the mod's code be split across several files under src/?
  3. Can an agent take a real screenshot of the terminal pane, or only a text render from the plugin test kit?
  4. Does Codex read a global ~/.codex/AGENTS.md?

How the hard parts work

PartHow
Install/plugin install studio-201 --marketplace asarelcastellanos/studio-201. The first session after install runs setup once and asks before changing anything.
Connecting ~/.claudeSetup copies AGENTS.md to ~/.claude/studio-201/AGENTS.md and adds one import line to ~/.claude/CLAUDE.md. Codex gets a link at ~/.codex/AGENTS.md.
Update/studio update runs claude plugin marketplace update and claude plugin update, copies the new AGENTS.md, reloads, and prints the old and new versions.
Usage and limitsClaude Code gives mods the context fill, cost, and 5h and 7d percent with reset time. The mod takes a reading each turn.
ForecastReadings are kept on this Mac across sessions, about 7 days' worth. A straight line through recent readings gives the time 100% is reached, compared with the reset time.
AgentsClaude Code lists each agent with its model, start time and tokens. The mod records finish times itself. Clicking an agent asks Claude Code to show its transcript.
PolicyThe mod sees every tool call before it runs. It refuses file edits from the main session and any gh pr merge or git push that targets main.

Decisions to approve

Each card is a choice the build would otherwise make without asking. The recommended option is first.

K1 · Where the plugin livesAt the repo root.Alternative: in a plugins/studio-201/ folder.
ForShortest install path. The standard layout for a one-plugin repo.
AgainstInstalls carry the docs folder too. It's small, so no real cost.
K2 · Mod languageTypeScript.Alternative: plain JavaScript.
ForClaude Code ships the types, so mistakes get caught before the mod loads.
AgainstNone found.
K3 · How rules reach every projectSetup copies AGENTS.md into ~/.claude and imports it from there. Update refreshes the copy.Alternative: import straight from the plugin's install folder.
ForThe path stays fixed across versions.
AgainstOne copied file to keep in sync. Update handles it.
K4 · First-run setupRuns on the first session after install and asks you once before changing ~/.claude or turning off the workbench mods.Alternative: a manual /studio setup.
ForInstall stays one step (C1). You still confirm.
AgainstA prompt at the start of that one session.
K5 · Where forecast readings liveOn each Mac, inside Claude Code's mod storage.Alternative: a file in the repo.
ForNo files to commit, nothing private in a public repo.
AgainstEach Mac learns its own pace. The percent itself is account-wide.
K6 · QA evidence for the paneAgents capture a text render of the pane from the plugin test kit. You take one real screenshot per feature at merge review.Alternative: agents take real screenshots, if the spike shows they can.
ForWorks without giving agents screen recording access.
AgainstFive screenshots from you during v0.1.
K7 · Where evidence is storedIn qa/v0.1/ in the repo, linked from each issue.Alternative: attached to issue comments only.
ForVersioned with the code. Survives a Mac cleanup.
AgainstImages add weight to the repo over time.
K8 · Policy enforcementInside the mod, on every tool call.Alternative: shell hooks in settings.
ForOne install, no settings edits, same code as the pane.
AgainstTurning the mod off turns the policy off too.
K9 · How merges to main are caughtMatch gh pr merge on a PR whose base is main, and git push to main.Alternative: GitHub branch protection.
ForWorks even though agents act as you.
AgainstPattern matching. An agent calling the GitHub API directly would slip past. Branch protection can be added later as a second layer.
K10 · Guardrails during the buildThe workbench's policy stays on until you install Studio 201 at the end.Alternative: install each feature as it merges.
ForNever zero guardrails, never two at once.
AgainstYou only see Studio 201 live at the end. Feature QA happens through test renders until then.
